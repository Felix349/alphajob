# AlphaJob 开发命令手册

> 所有日常命令的速查表。Windows 上用 PowerShell 或 Git Bash 都可以，路径以项目根目录 `E:\AlphaJob` 为准。

---

## 1. 每天开工 / 收工

### 开工（三步）

```bash
# ① 启动数据库和 Redis（先打开 Docker Desktop）
cd E:/AlphaJob
docker compose up -d

# ② 启动后端（新开一个终端）
cd E:/AlphaJob/backend
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# ③ 启动前端（再新开一个终端）
cd E:/AlphaJob/frontend
pnpm dev
```

| 地址 | 用途 |
|---|---|
| http://localhost:3000 | 前端页面 |
| http://127.0.0.1:8000/api/docs | 后端接口文档（可以直接在网页上调接口） |
| http://127.0.0.1:8000/api/health | 健康检查 |

### 收工

```bash
# 前端、后端：在各自的终端按 Ctrl + C

# 停止数据库和 Redis（数据会保留）
cd E:/AlphaJob
docker compose down
```

> ⚠️ `docker compose down -v` 会**删除数据库里的所有数据**，除非想彻底重置，否则不要加 `-v`。

## 2. 第一次在新电脑上运行

```bash
cd E:/AlphaJob
cp .env.example .env              # 然后编辑 .env：改 JWT_SECRET，填 DEEPSEEK_API_KEY

# 生成随机的 JWT_SECRET
cd backend
uv run python -c "import secrets; print(secrets.token_urlsafe(48))"

docker compose up -d              # 在项目根目录
cd backend && uv sync && uv run alembic upgrade head
cd ../frontend && pnpm install
```

## 3. 后端（在 `backend/` 目录下）

### 运行与依赖

| 目的 | 命令 |
|---|---|
| 启动开发服务器（改代码自动重启） | `uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000` |
| 安装 / 同步依赖 | `uv sync` |
| 添加依赖 | `uv add 包名` |
| 添加开发依赖（测试、lint 等） | `uv add --dev 包名` |

> 修改 `.env` 后要**重启后端**才会生效（配置只在启动时读取）。

### 测试与代码检查

| 目的 | 命令 |
|---|---|
| 运行全部测试 | `uv run pytest` |
| 只跑某个文件 | `uv run pytest tests/test_auth.py` |
| 只跑名字包含某个词的测试 | `uv run pytest -k parse_jd` |
| 显示详细输出 | `uv run pytest -v` |
| 测试卡住时打印调用栈 | `uv run pytest -o faulthandler_timeout=15` |
| 代码检查 | `uv run ruff check .` |
| 代码检查并自动修复 | `uv run ruff check . --fix` |
| 格式化代码 | `uv run ruff format .` |
| 提交前一键检查 | `uv run ruff check . && uv run ruff format --check . && uv run pytest` |

### 数据库迁移（Alembic）

| 目的 | 命令 |
|---|---|
| 改了模型后生成迁移文件 | `uv run alembic revision --autogenerate -m "描述改动"` |
| 执行迁移到最新 | `uv run alembic upgrade head` |
| 回滚一步 | `uv run alembic downgrade -1` |
| 回滚到空库 | `uv run alembic downgrade base` |
| 查看当前版本 | `uv run alembic current` |
| 查看迁移历史 | `uv run alembic history` |

> 生成迁移后，**先打开迁移文件检查一遍**再执行。自动生成不一定完全正确。

### JD 解析评估（会真实调用大模型，花几分钱）

| 目的 | 命令 |
|---|---|
| 跑全部用例（虚构 + 本地真实 JD） | `uv run python scripts/eval_parse_jd.py` |
| 只跑指定用例 | `uv run python scripts/eval_parse_jd.py --only english,no-company` |
| 每条跑 3 次，检查稳定性 | `uv run python scripts/eval_parse_jd.py --repeat 3` |

结果保存在 `backend/evals/jd_parse/results/`（不提交）。用例说明见 [评估集 README](../backend/evals/jd_parse/README.md)。

### 导出接口文档

```bash
uv run python scripts/export_openapi.py ../frontend/openapi.json
```

一般不用手动运行，前端的 `pnpm gen:api` 会自动调用它。

## 4. 前端（在 `frontend/` 目录下）

| 目的 | 命令 |
|---|---|
| 启动开发服务器 | `pnpm dev` |
| 安装依赖 | `pnpm install` |
| 添加依赖 | `pnpm add 包名` |
| 添加开发依赖 | `pnpm add -D 包名` |
| **后端接口改了之后**，重新生成前端类型 | `pnpm gen:api` |
| 类型检查 | `pnpm typecheck` |
| 代码检查 | `pnpm lint` |
| 格式化代码 | `pnpm format` |
| 检查格式（不修改） | `pnpm exec prettier --check src` |
| 生产构建 | `pnpm build` |
| 添加 shadcn/ui 组件 | `pnpm dlx shadcn@latest add 组件名`（例如 `dialog`） |
| 提交前一键检查 | `pnpm typecheck && pnpm lint && pnpm exec prettier --check src && pnpm build` |

> shadcn 询问“是否覆盖 button.tsx”时停住不动：在命令前加 `echo n|`，例如 `echo n| pnpm dlx shadcn@latest add dialog`。

## 5. 数据库与 Redis

```bash
cd E:/AlphaJob

docker compose ps                         # 查看容器状态
docker compose logs -f postgres           # 查看数据库日志（Ctrl + C 退出）

# 进入数据库命令行（\dt 列出所有表，\d 表名 查看表结构，\q 退出）
docker compose exec postgres psql -U alphajob -d alphajob

# 直接执行一条 SQL
docker compose exec -T postgres psql -U alphajob -d alphajob -c "SELECT email, created_at FROM users;"

# 查看大模型调用记录（成本统计）
docker compose exec -T postgres psql -U alphajob -d alphajob -c "SELECT feature, model, input_tokens, output_tokens, latency_ms, success, created_at FROM llm_call_logs ORDER BY created_at DESC LIMIT 20;"

# Redis
docker compose exec redis redis-cli ping  # 应返回 PONG
```

| 数据库 | 用途 |
|---|---|
| `alphajob` | 开发用 |
| `alphajob_test` | 自动化测试专用，每次测试都会清空 |

## 6. Git 与 GitHub 工作流

### 做一个新功能（以 W3 为例）

```bash
git switch main && git pull                 # ① 从最新的 main 开始
git switch -c feat/w3-match                 # ② 新建功能分支

# …写代码、跑检查…

git add -A                                  # ③ 暂存所有改动
git status                                  #    确认没有误加 .env 等敏感文件
git commit -m "feat: 简短描述"               # ④ 提交

git push -u origin feat/w3-match            # ⑤ 推送到 GitHub
gh pr create --base main --fill             # ⑥ 开 PR（会触发 CI）
gh pr checks                                # ⑦ 查看 CI 状态
gh pr merge --rebase                        # ⑧ CI 通过、审核完后合并

git switch main && git pull                 # ⑨ 本地同步
```

### 常用查看命令

| 目的 | 命令 |
|---|---|
| 当前在哪个分支、有哪些改动 | `git status` |
| 查看具体改了什么 | `git diff` |
| 提交历史 | `git log --oneline -10` |
| 列出 PR | `gh pr list` |
| 在浏览器打开仓库 | `gh repo view --web` |
| 查看最近的 CI 运行 | `gh run list --limit 5` |
| 查看某次 CI 失败的日志 | `gh run view <运行编号> --log-failed` |

### 提交信息规范（Conventional Commits）

| 前缀 | 用途 |
|---|---|
| `feat:` | 新功能 |
| `fix:` | 修 bug |
| `docs:` | 只改文档 |
| `refactor:` | 重构（不改行为） |
| `test:` | 只改测试 |
| `chore:` | 杂项（依赖、配置） |

## 7. 配置项速查（`.env`）

| 配置 | 说明 |
|---|---|
| `JWT_SECRET` | 登录令牌的签名密钥，必须改成随机长字符串 |
| `LLM_PROVIDER` | 默认大模型：`deepseek` / `qwen` / `openai` / `anthropic` |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | DeepSeek 的 Key 和模型名 |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | Claude（可选） |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | OpenAI（可选，必须同时填模型名） |
| `DASHSCOPE_API_KEY` / `QWEN_MODEL` | 通义千问与语音转写（W4 开始使用） |
| `COOKIE_SECURE` | 本地开发为 `false`，上线 https 后改为 `true` |

> `.env` 已被 Git 忽略。**永远不要把 Key 提交到仓库，也不要发在聊天里。**

## 8. 常见问题

| 现象 | 原因与解决 |
|---|---|
| 后端或测试**连数据库卡住不动** | Windows 上 `localhost` 会先走 IPv6，Docker 的 IPv6 端口转发连不通。`.env` 里的地址必须用 `127.0.0.1` |
| `alembic` 报 **GBK 解码错误** | `alembic.ini` 里不能写中文（Windows 用 GBK 读取） |
| `package.json` **解析失败**，提示 `Unexpected token` | 文件开头被写入了 BOM，通常是 PowerShell 5 的 `Set-Content -Encoding utf8` 造成的。改用编辑器以“UTF-8（无 BOM）”保存 |
| 前端报 **字体加载失败** | 已改用本地 `geist` 字体包；如果又出现，检查是否误用了 `next/font/google` |
| 前端报 **“outside of `<Suspense>`”** | Next.js 16 的 cacheComponents 要求：读取 URL（`usePathname`、`useParams`）或当前时间的组件，必须包在 `<Suspense>` 里 |
| 前端改了配置**不生效、报奇怪的错** | 停掉 `pnpm dev`，删除 `frontend/.next` 文件夹后重启 |
| 新建投递时提示 **“智能解析暂不可用”** | `.env` 里没有填 API Key，或填完没有重启后端 |
| 改了 `.env` **不生效** | 重启后端 |
| CI 报“**接口类型与后端不同步**” | 本地运行 `pnpm gen:api`，然后提交生成的 `openapi.json` 和 `schema.d.ts` |
| 端口被占用 | 用 `netstat -ano \| findstr :8000` 查看占用的进程号，再用 `taskkill /PID <进程号> /F` 结束它 |
